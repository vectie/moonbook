# MoonBook capability truth

MoonBook owns two canonical, pack-local operations:

- `moonbook/bookkeeper.outcome.close@0.1.0` replaces the aspirational canvas
  label `bookkeeper.close-loop`.
- `moonbook/wiki.requirements.prepare@0.1.0` deterministically prepares an
  evidence-bound, review-pending requirements packet.

MoonWiki is functionality inside MoonBook. It is not a product, pack, app or
agent runtime. Historical `product_id: moonwiki` advertisements are
non-callable compatibility metadata; new graphs must bind `product_id:
moonbook` and an exact operation reference above. MoonClaw remains the sole
agent runtime, although requirements preparation itself invokes no agent.

The three capability-truth inputs have separate owners:

- [`../pack.json`](../pack.json) is product-owned and declares the operation
  and versioned schemas.
- [`moonflow.adapter-declaration.v1.json`](moonflow.adapter-declaration.v1.json)
  declares the pack-local MoonFlow v2 binding and its digital-artifact claim
  ceiling.
- health is generated by the installation host from an actual focused check;
  it is never committed as a permanently healthy repository file.

Generate a short-lived `moonflow.adapter-health.v1` document with:

```sh
moon run cmd/moonbook_adapter -- health \
  <checked-at-ISO8601> \
  <valid-until-ISO8601> \
  <workspace-relative-evidence-path> \
  <sha256:evidence-digest>
```

The health document covers exactly both operation versions above. MoonGate may
project them only after MoonFlow compiles the manifest, declaration and
expiring attestation into a conformant capability catalog.
